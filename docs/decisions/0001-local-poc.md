# ADR 0001 — Isolated, source-of-truth-led local POC

Status: accepted for evaluation (not production approval). Date: 2026-10-23.

## Context and evidence

The repository initially contained only a two-line README. The host is Apple Silicon (arm64), Docker 29.8.2 / Compose v5.5.0 on OrbStack with an 8 GiB VM; an unrelated Dependency-Track stack already owns loopback ports 8080/8081. Do not stop or reuse it. Dependency-Track's [published Compose](https://dependencytrack.org/docker-compose.yml) uses separate API, frontend and PostgreSQL containers, currently pinned to 5.2.1 for the applications and a PostgreSQL major tag. Dependency-Track is Apache-2.0. [DefectDojo CE install](https://docs.defectdojo.com/get_started/open_source/installation/) recommends its own Compose; it is BSD-3-Clause. Its ARM64 Debian image gets unit tests but not integration/performance tests. Its Compose requires Django, nginx, initializer, worker, scheduler, Postgres, Valkey and media. The upstream example defaults to public binding and development credentials: never reuse those defaults on a network. [Trivy](https://github.com/aquasecurity/trivy/releases) is an on-demand scanner (v0.76.1 at evaluation), not a permanent service. Its image and vulnerability database availability must be checked at runtime.

## Decision

Use a local-only Dependency-Track project (`compose.yaml`) with dedicated Postgres 18, persisted API data, and loopback ports 18080/18081. Require operator-supplied `DT_DB_PASSWORD`; no password or API key goes into Git. Keep the database on an internal network; API additionally reaches the internet for advisory feeds. Keep DefectDojo CE as a **separate, version-selected upstream Compose subproject** with a local-only override; do not combine its schema or worker topology with Dependency-Track's. Use Trivy as an ephemeral CLI/container job and CycloneDX JSON as the SBOM format. Keep a Git-versioned YAML catalog as the canonical product/service/release/deployment mapping, not an invented vulnerability database. Feed status depends on outbound access and can lag behind SBOM import. Source SBOM, image SBOM and deployed-artifact SBOM are distinct evidence.

Versions and license sources: [Dependency-Track release](https://github.com/DependencyTrack/dependency-track/releases/tag/5.2.1), [DefectDojo CE release](https://github.com/DefectDojo/django-DefectDojo/releases/tag/3.4.202), [Trivy release](https://github.com/aquasecurity/trivy/releases/tag/v0.76.1), [Dependency-Track license](https://github.com/DependencyTrack/dependency-track/blob/main/LICENSE.txt), [DefectDojo license](https://github.com/DefectDojo/django-DefectDojo/blob/master/LICENSE.md). Exact image manifests and local compatibility remain runtime checks, not claims of verified compatibility.

## Consequences and boundaries

This POC is not a production Azure deployment: local HTTP, product-wide administrator account, no SSO/RBAC integration, no external TLS, no off-host backup or restore drill. Before Azure rollout add TLS gateway, team/product authorization, vault-backed credentials, network egress policy, audit/backup retention, digest-pinned images, upgrade tests and image signature/provenance checks. Never forward either admin API or port beyond loopback by changing a hostname alone. Do not scan production systems. No SAURON, Datadog ingestion or Slack secret-bearing notifications until trustworthy catalog and findings exist. GitHub private-repo [SARIF code scanning requires qualifying paid security entitlement](https://docs.github.com/en/code-security/how-tos/scan-code-for-vulnerabilities/integrate-with-existing-tools/uploading-a-sarif-file-to-github); artifact/PR summary is the free fallback, without publishing sensitive findings.

## Amendment — single stack (2026-10-26)

The original decision kept DefectDojo as a separate Compose subproject. That was **superseded**: two projects meant two networks, two secret sets, two command paths, and a subdirectory project that ignored the root `.env`. The user requires one published stack. All services now live in the root `compose.yaml` as project `barad-dur`, with `dojo-*` names to avoid colliding with Dependency-Track. Isolation is preserved by network, not by project: `dt-internal` and `dojo-internal` are `internal: true`, and only three loopback UI ports are published. Scanner images (`trivy`, `syft`, `cyclonedx`) join as `profiles: [tools]` services, so they never run as idle daemons. Volumes are adopted by explicit name to make accidental empty-database startups fail loudly. See "Consolidation into a single stack" in `docs/operations/poc-validation.md`.
